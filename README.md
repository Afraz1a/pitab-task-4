# CitizenSense — NLP-Based Public Feedback Classification and Insight System

AIRI Team PITB — AI Internship Task 4 (End-to-End NLP Project)
Option selected: **A — Public Complaint Classifier**, with **Sentiment** as the required secondary output
(via a Hugging Face pretrained pipeline) and **Priority / Keywords / Summary / Suggested Department**
as additional insight-generation features.

> This is a learning prototype built for the internship task, **not** a production
> government complaint-management system. Model predictions should be treated as
> suggestions, not final decisions.

## 1. Problem

Organizations receive large volumes of public feedback and complaints as free text.
Reading and triaging each message manually is slow and inconsistent. CitizenSense takes
a short feedback message and automatically produces:

- **Category** (Roads/Infrastructure, Water Supply, Electricity, Sanitation, Health,
  Education, Traffic, General)
- **Sentiment** (Negative / Neutral / Positive)
- **Priority** (Low / Medium / High / Urgent)
- **Keywords**
- **Short summary**
- **Suggested department**

## 2. Dataset

The dataset is **synthetic**, generated by [`data/generate_dataset.py`](data/generate_dataset.py)
from ~100 hand-written templates across the 8 categories, combined with randomized area
names and durations to create natural variation. This was a deliberate choice given the
one-week timeline and the task's privacy rules (no real complaint data, phone numbers,
CNIC numbers, or addresses were used or are needed).

- **739 total samples**, deduplicated, across **8 categories** (min class size 72).
- Each sample also carries a **Sentiment** label (Negative/Neutral/Positive) and a
  **Priority** label (Low/Medium/High/Urgent), both assigned at generation time.
- A small slice (~6%) is written in **Roman Urdu / mixed English-Urdu**, to exercise
  multilingual robustness (Option C's theme), e.g. `"hamare area ki road bohat kharab
  hai aur pani jama hota hai"`.
- A further slice is **deliberately label-ambiguous**: the same vague wording (e.g.
  *"There is a problem in our area that needs attention."*) is randomly assigned one of
  several plausible categories. This mirrors how short, vague real-world complaints are
  genuinely hard to classify from text alone, and is what produces the honest
  misclassifications analyzed in Section 7 below — rather than only ever producing a
  perfectly separable, unrealistically easy dataset.

Data source note (per task rule #4/#5 in Section 7): **100% synthetic, intern-written
templates** — no public/Kaggle dataset was used. This is stated here explicitly as required.

Raw data: [`data/raw/citizen_feedback_raw.csv`](data/raw/citizen_feedback_raw.csv)
Cleaned + split data: [`data/processed/`](data/processed/) (`train.csv` 70%, `val.csv` 15%, `test.csv` 15%, stratified by category)
Label map: [`data/labels.csv`](data/labels.csv)

## 3. Preprocessing

Implemented in [`data/preprocess.py`](data/preprocess.py):

| Step | Applied | Why |
|---|---|---|
| Lowercasing | Yes | Normalizes English text for TF-IDF |
| Whitespace cleanup | Yes | Removes stray double spaces from templating |
| URL removal | Yes | Required by task rules; defensive even though dataset has none |
| Phone number pattern removal | Yes | Privacy rule — strips any digit sequences that look like phone numbers |
| Punctuation handling | Yes (light) | Keep `. , ! ?` (mild sentence structure signal), strip the rest |
| Duplicate removal | Yes | Exact-text dedup after cleaning |
| Missing value handling | Yes | Drop empty/NaN rows |
| Tokenization | Yes | Simple regex tokenizer used for keyword extraction; TF-IDF tokenizes internally for modeling |
| Train/val/test split | Yes | 70/15/15, **stratified by category** |
| Label encoding | Yes | `sklearn.LabelEncoder` for category, sentiment, priority |
| Stopword removal | **No** | Complaints are short; words like "no", "not" carry sentiment/priority signal that stopword lists often remove |
| Stemming/Lemmatization | **No** | Not needed at this vocabulary size/short-text scale; would add complexity without clear benefit here |
| Roman Urdu normalization | **No** (left as-is) | Out of scope for a one-week baseline; flagged as a future improvement |

## 4. Baseline model

[`train_model.py`](train_model.py) trains **TF-IDF (unigrams+bigrams, max 5000 features) +
Logistic Regression (`class_weight="balanced"`)** for category classification, using
scikit-learn's `Pipeline`.

**Test set results** (110 samples, 8-class):

| Metric | Value |
|---|---|
| Accuracy | 0.928 |
| Weighted Precision | 0.933 |
| Weighted Recall | 0.928 |
| Weighted F1 | 0.929 |

Full per-class report: [`outputs/classification_report.txt`](outputs/classification_report.txt)
Confusion matrix: [`outputs/confusion_matrix.png`](outputs/confusion_matrix.png)
Sample predictions (30): [`outputs/sample_predictions.csv`](outputs/sample_predictions.csv)

### Interpretation

- **Best-performing classes:** Electricity (F1 1.00), Roads/Infrastructure and Sanitation
  (F1 ≈ 0.96–0.97) — these have the most distinctive vocabulary ("water pipeline",
  "transformer", "garbage").
- **Weakest classes:** General and Water Supply (F1 ≈ 0.86) — "General" is inherently the
  catch-all category and overlaps in wording with almost every other class; several of
  the deliberately ambiguous templates land here.
- **Main confusion pairs:** Roads/Infrastructure ↔ Water Supply/Sanitation (shared "water",
  "road" vocabulary), Electricity ↔ General (short, generic phrasing), Health ↔ Education
  (shared "staff" vocabulary).
- **Why accuracy alone can mislead:** with 8 unevenly-sized classes, a model could score
  high accuracy while performing poorly on a minority class (e.g. General, 13 test
  samples). Per-class precision/recall/F1 and the confusion matrix are needed to see that.
- **Why F1 matters for imbalance:** F1 balances precision and recall per class, so a model
  that just predicts the majority class to inflate accuracy is penalized, unlike raw
  accuracy.
- **More data would help** the weakest/ambiguous classes most directly — the confusion is
  concentrated in genuinely vague wording, which more labeled, more distinctive examples
  (and ideally a transformer fine-tuned with more context) would resolve better than a
  bag-of-words baseline ever can.

## 5. Hugging Face / transformer component

[`app/sentiment.py`](app/sentiment.py) uses the **Hugging Face `sentiment-analysis`
pretrained pipeline** (`distilbert-base-uncased-finetuned-sst-2-english`) to classify
Sentiment (the task's required secondary output alongside Category). Since that pipeline
is binary (POSITIVE/NEGATIVE), a confidence threshold (0.70) is used to fall back to
**Neutral** when the model isn't confident — giving the 3-way Negative/Neutral/Positive
label CitizenSense needs. This satisfies the "transformer-based model or Hugging Face
pipeline" requirement (Option A: pretrained pipeline) without requiring local fine-tuning.

## 6. Keyword extraction & summarization

[`app/utils.py`](app/utils.py) implements **both**:

- **Keyword extraction:** per-document TF-IDF over unigrams+bigrams (stopwords removed),
  top-5 highest-weighted terms.
- **Summarization:** a structured, template-based one-liner ("Citizen reports a `<category>`
  issue: `<cleaned text>`"), matching the task's "Complaint Insight Card" style
  (Section 12, Option C). A heavy abstractive summarizer was judged unnecessary overhead
  for single-sentence complaint text in a one-week prototype; this is documented as a
  deliberate scope decision.

## 7. Error analysis

[`error_analysis.py`](error_analysis.py) manually reviews **15 cases** (14 true
misclassifications from the combined validation+test predictions, plus 1 low-confidence
but correct "weak" prediction), each with an inferred **Error Type** and **Possible
Reason**. Table: [`outputs/error_analysis.csv`](outputs/error_analysis.csv).

**Suggested improvements** ([`outputs/improvement_suggestions.txt`](outputs/improvement_suggestions.txt)):
1. Add more labeled examples for the weaker classes (General, Water Supply, Health).
2. Balance ambiguous/ overlapping classes with more distinctive examples.
3. Improve label guidelines for short/vague complaints (e.g. default to General).
4. Expand Roman Urdu / multilingual training data beyond the current bonus slice.
5. Fine-tune a transformer (e.g. DistilBERT), which can use word order/context the
   bag-of-words baseline cannot.
6. Add a human-review queue for predictions below a confidence threshold.

## 11. Limitations

- Dataset is synthetic/templated, not real citizen complaints — real-world text will be
  noisier and may need more preprocessing (spelling errors, emoji, slang).
- The 8 categories are fixed; multi-label complaints (an issue spanning two categories)
  are forced into a single label here.
- Sentiment uses a general-purpose English sentiment model; it is not fine-tuned for
  civic-complaint phrasing or for Roman Urdu text.
- Priority at inference time (in the demo) is a simple keyword+sentiment heuristic, not a
  trained classifier — the dataset's priority labels were used for scoping the template
  design, not for a dedicated priority model, given the one-week timeframe.
